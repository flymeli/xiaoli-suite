# 校哩（xiaoli-suite）

校哩是面向可核验学生资格的校园社区。学生身份和学校归属要分开看。默认内容在本校；主动选择后，可以让全站已认证学生看见，不是互联网公开。首版先做社区和受控私信，群聊、商业化和运营后台都往后放。

本仓库现在有两层材料：已经同步的分析文档，以及从用户 OpenDesign 项目 `6de335a6` 导入的学生端原型。还没有业务工程，也不要在这里部署、购买云资源或提交平台申请。

## 怎么读

产品方向以 [docs/02-决策记录.md](docs/02-决策记录.md)（V0.4，含 DEC01–DEC10 和 TECH01–TECH06）为准。认证证据以 [docs/04-认证接入可行性研究.md](docs/04-认证接入可行性研究.md)（V0.3）为准，技术建议以 [docs/05-技术选型与分阶段数据治理建议.md](docs/05-技术选型与分阶段数据治理建议.md)（V0.4）为准。这三份里写着「已确认」的，是方向；写着「待验证 / 待申请 / 待 PoC / 未冻结」的，不能改成已经上线或已经获准。

[docs/03-技术与数据治理研究计划.md](docs/03-技术与数据治理研究计划.md) 是更早的研究计划。它里面「Flutter / Go / 腾讯云还不是既定选型」这句话，记录的是计划成文时的前提。后来的拍板在 02 的 TECH 和 05 的 V0.4，不要用计划稿把已经确认的技术栈说回去，也不要把 05 里的建议拓扑、单价和 RPO 当成已经买好。

`source/` 里的产品规格、启动包、技术旧稿和墙墙 HTML 只作为这些分析的历史依据，没有整份放进仓库当现行需求。和 02 冲突的地方，按 02 的冲突清单处理，源文件本身没有改。

## 原型

学生端在 [prototypes/mobile](prototypes/mobile)。来源和没有带入的编辑器文件见 [prototypes/mobile/SOURCE.md](prototypes/mobile/SOURCE.md)。用静态服务打开 `index.html` 即可，认证按钮不会访问微信、支付宝、学信网或短信。

```bash
cd prototypes/mobile
npm test
```

测试使用本机 Chrome 打开真实页面，检查认证 / 学校状态和原有校园、广场、发布、消息、我的、视频，并在 360、390、430 宽看有没有横向溢出。
