- 版本：盘点稿 V0.1
- 日期：2026年11月16日（Asia/Shanghai）
- 盘点对象：恒在 OpenDesign 中制作的学生端部分原型，项目目录 `/workspace/xiaoli/od-proto/6de335a6-f9e2-42a5-b799-5409948a2f2e/`，`index.html` 最近修改时间为 2026年11月6日 23:08（Asia/Shanghai）。项目 ID：`6de335a6-f9e2-42a5-b799-5409948a2f2e`。
- 对照依据：《校哩App 产品规划与需求规格 V1.0》（2026-11-06 Markdown）、`xiaoli_design_tokens_v1.json`、UIUX 手册 V1.0。墙墙 HTML 全页原型只作参考，不作为继续完善的底稿。
- 本文只整理现状，未改动原型源文件。

OpenDesign 这份稿已经用「校哩」品牌、五入口「校园 / 广场 / 发布 / 消息 / 我的」、六类频道、仅本校 / 全站学生、学籍报告指引和受控私信请求，把学生端 UI-01 至 UI-34 的主路径搭起来了，并且没有放入群聊、钱包或开屏广告。它是后续完善原型的正确起点。当前主要缺口不在「有没有页面」，而在认证与学校状态不完整、异常路径不足、登录注册超出首期范围，以及视觉数值尚未对齐正式 token。

## 1. 现有页面与交互

`index.html` 是单页应用。路由写在 `const routes` 里，由 `state.route` 和 `go()` / `back()` 切换。真正写在 DOM 里的固定 ID 很少；下面以**路由 ID**为准（这是页面的稳定标识），并附上文件内标注的 UI 编号。

### 1.1 全局壳与浮层

| ID | 说明 |
|---|---|
| `app` | 页面根节点。渲染时写入顶栏、主滚动区和底栏。 |
| `screen-scroll` | 主滚动容器。`go()` 会记下离开前的滚动位置，`back()` 再恢复。 |
| `toast` | 短时反馈，约 2.2 秒后关闭。用于点赞、收藏、分享、校验失败、授权成功等。 |
| `confirm-dialog` / `dialog-title` / `dialog-copy` / `dialog-confirm` | 通用确认框。用于作品「更多操作」、注销等需要先说明后果的动作。 |
| `provider-dialog` / `provider-title` / `provider-copy` | 微信 / QQ / 支付宝「扫码授权」演示框。不在 P0 登录范围内，见第 6 节。 |
| `editor-exit-dialog` | 离开编辑器时选择保存草稿、放弃或继续编辑。 |
| `campus-video` | 校园视频详情使用的原生 `<video>` 节点。 |

底栏由 `tabbar()` 生成，五个入口与产品规格一致：校园 `campus`、广场 `plaza`、发布 `create`、消息 `messages`、我的 `mine`。发布按钮使用加号容器。消息入口带未读点「3」。只有标注了底栏归属的页面才显示底栏；欢迎、登录、认证等账号页不出现五入口，这一点符合「未认证进入认证服务区」的方向。

顶栏由 `topbar()` 生成。欢迎、登录、注册、搜索、校园、广场、消息使用各自页内页眉；其余页面显示返回、标题，部分标题下有「已认证学生」。我的页右侧是设置。返回支持系统式后退，并恢复滚动位置。

### 1.3 主要交互能力

- 路由前进与后退，校园 / 广场来源记在 `state.origin`，滚动位置可恢复。
- 内容卡点击进详情，评论按钮进评论页；点赞、收藏可切换并 toast，分享提示「外部只显示品牌通用说明」。
- 校园与广场的频道、布局、精选 / 最新 / 关注可切换；广场可按学校过滤。
- 发布链路：选题 → 编辑（自动保存）→ 范围确认 → 上传 / 审核进度 → 草稿箱恢复。
- 视频：演示进度或原生播放、静音、结束重播、失败重试。
- 私信：发送请求、接收方接受演示、进入会话、发送文字。
- 举报与拉黑、申诉、续验、退出登录、注销确认、大字模式。
- 登录校验、获取验证码、协议勾选；第三方登录为演示弹层。

演示人物与学校沿用设计手册约定：林同学、阿澈属南川大学，小禾属北屿理工大学。示例内容包括「图书馆周末有哪些安静座位」「傍晚的操场有点好看」「20 秒校园采访」。这一点是对齐的。

## 2. 与 DESIGN.md、设计 token 是否一致

### 2.1 项目内 DESIGN.md 不能当校哩规范

同目录的 `DESIGN.md` 标题是 “Hims App — Style Reference”，描述的是医疗健康产品 Hims 的风格：唯一彩色强调为紫色 `#5d48db`，字体 Sofia，圆角 30–52，大投影，白底黑字。这与校哩的校园蓝、系统字体、卡片圆角 16、内容卡默认无阴影的规定不是同一套系统。

它更像是 OpenDesign 带入或误留的风格参考，**不能作为校哩视觉依据**。现行视觉应以仓库外的《校哩App_UIUX设计规范与OpenDesign提示词_V1.0.md》和 `xiaoli_design_tokens_v1.json` 为准。

一个旁证：2026-10-30 的早期画布截图里，原型还曾有「系统 V1.0 / 组件 / UI-10 校园 / UI-11 广场」以及「校哩设计系统」色板页，浅色主色、画布 `#F7F8FA`、正文 `#1C2028` 更接近 token。该设计系统页在 11 月 6 日的 `index.html` 里已经不存在。

### 2.2 `index.html` 与 `xiaoli_design_tokens_v1.json` 对照

原型使用自有 CSS 变量，没有引用 token 文件。语义接近，数值多数未锁定到建议基线。

| 项目 | Token / 手册建议 | 当前原型 | 判断 |
|---|---|---|---|
| 主色 brand.primary | `#2457E7` | `#4B6CB7` | 偏灰蓝，不是校园蓝 |
| 画布 canvas | `#F7F8FA` | `#F5F5F7` | 接近但不一致 |
| 正文 text.primary | `#1C2028` | `#1D1D1F` | 接近 |
| 次级 / 三级文字 | `#5D6573` / `#646C78` | `--text-2`、`--meta` 与此相同 | 一致 |
| 成功色 | `#176B47` / `#EAF5EF` | 相同 | 一致 |
| 危险色 | `#B42318` / `#FDEEEB` | 相同 | 一致 |
| 警告色 | `#8A4B0F` | `#947116` | 不一致（早期色板即如此） |
| 主按钮 | 实心主色、白字、高度 52、圆角 12 | 后期样式把主按钮也改成白底黑描边，高度 50；登录页可见 | 偏离，主动作不够突出 |

| 已选标签 | 主色字、字重 600、2 单位主色描边 | 有主色和描边，字重和热区（芯片可视高度约 34–38）未完全达到 48 热区 | 部分达到 |
| 点击热区 | 最小 48×48 | 部分图标按钮和图标统计偏小 | 部分达到 |
| 焦点环 | 使用主色 | `--focus-ring` 仍是 `rgba(93,72,219,.22)`，即 Hims 紫 | 明显串入了 DESIGN.md 的色 |
| 深色模式 | token 提供完整暗色语义 | 设置文案写明固定浅色纸感画布 | 未做，与手册「跟随系统」有差距，但可作为原型阶段取舍 |

结论：产品结构和文案大方向已经按校哩规格走；**视觉还没有收敛到正式 token**。继续完善时应先统一主色、实心主按钮、字号和底栏，不要再引用 Hims 的 DESIGN.md。

## 4. 功能盘点表（按 V1.0 P0 / P1）

覆盖取值：

- **有**：主路径可点，关键规则在界面上能看出来或能走通。

- **无**：当前原型没有对应界面，或完全无法演示。

### 4.8 P0 覆盖率

对学生端可演示的 P0 功能行（第 4.1–4.5 节，已排除「冲突」项和已正确后置的群聊，后台第 4.6 节单列）逐项核对如下：

- 加上 P0 后台 6 类工作区（均记为无、另项交付）后，综合完成度约为 **51%**。对外说明建议采用：**学生端主路径接近六成，完整 P0（含后台和异常状态）大约一半。**

## 5. 超范围或与规格冲突的原型内容

这些不是「还没做」，而是「做了但不该按现在这样留在 P0 主路径里」。

| 内容 | 位置 | 问题 | 建议 |
|---|---|---|---|
| 独立「注册账号」+ 设置密码 | `register` | 首期账号是手机验证码，登录成功后进认证中心，不必再设一套密码注册。 | 收回独立注册，或降为可选项并写清「不是学生资格」。主按钮回到「登录并进入认证」。 |
| 微信 / QQ / 支付宝登录 | `loginOptions`、`provider-dialog` | 技术文档现行范围明确第三方登录不在首期；也容易让人以为授权登录就等于认证。 | P0 去掉入口。可留在画板外说明「后续可加」。 |
| 消息页「新建消息」+ 三个快捷入口结构 | `messages` | 快捷入口明显来自外部「市集」类 App。规格要求互动、系统、私信分开，请求不能混成已建立会话。 | 恢复或同时提供「互动 / 系统 / 私信」分段；新建消息必须先进入对方主页或请求，而不是像通讯录发起聊天。 |
| 评论配图与 @ | `comments` | 规格首期评论是文字、两层展示，没有单独的评论媒体需求。 | 先拿掉或标成未决，避免开发当成必做。 |
| 校园双列开关 | `campus` | 手册默认校园单列、广场双列。双列是过程稿里的实验，且对不齐曾被批注。 | 评审后决定：校园锁单列，或仅在大屏保留。 |
| 登录页缺少资格说明、主按钮不是实心主色 | `login` | 早期校哩稿更符合规格，当前稿更接近外部深色登录的结构（第三方、注册）。 | 回看 `image-1.png` 的信息结构，视觉改回 token。 |

## 7. 建议的完善顺序

原则：在这份 OpenDesign 稿上继续，不另起墙墙 HTML；先收冲突和主路径信息，再补异常状态；认证字段等待 DEC10，不提前画死；后台单独开项目。

**第一批，先收回冲突、补上主路径信息（不依赖未决 DEC 也能做）**

1. 用 token 校正主色 `#2457E7`、实心主按钮、字号不小于 12、底栏结构和焦点色；停止使用 Hims DESIGN.md。
2. 重做 `welcome`：补一句学生社区价值、目标人群和认证用途，并提供帮助入口。可参考但不必原样搬回「真实校园。完全不同。」
3. 重做 `login`：写清「登录后仍需学生认证」；协议可点进 `agreements`；主按钮「登录并进入认证」。去掉或移出第三方登录和密码注册。
4. 补协议正文示意和返回后保留表单。
5. 把「开始认证」接到 `authGuide` 再进入提交，而不是跳过指引。
6. 消息页恢复「互动 / 系统 / 私信」分段，私信请求单独成列；「新建消息」改为说明须从主页发起请求。

**第二批，补齐六条旅程的失败和权限状态（启动包 J1–J6）**

7. 认证：需补充、未通过（不同原因码）、超时不自动通过、通过但学校未开通（可逛广场、不能发布）。
8. 校园空态、学校暂停冻结作品；未开校身份下发布入口被拦截。
9. 私信：拒绝、冷却、过期、关闭联系、资格失效后不提供只读会话。
10. 详情 / 搜索 / 通知：无权限、已删除、已下架的统一结果，不露出封面和摘要。
11. 注销与数据副本的进度页；黑名单管理；设置里把仅互关可私信、关闭联系等拆开。

**第三批，在 DEC 结论后冻结**

12. DEC10 / PC01 有结论后，冻结 `authSubmit` 字段和帮助文案，补本人绑定步骤。
13. DEC01、DEC02 结论后，补年龄和学籍范围相关原因码。
14. 按评审结论决定校园是否保留双列、评论是否允许配图。

**第四批，独立项目**

15. A01 运营后台（UI-35–UI-40），桌面宽度，不放入本学生端。
16. F01 群聊仅在 DEC06 决定排期后另开项目。

完成标准仍以启动包 §3.8 为准：每条旅程不仅有成功路径，还要能点到返回、重试、拒绝、关闭和失效。本盘点不构成「原型已经验收通过」。
